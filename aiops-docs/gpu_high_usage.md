# GPU 利用率过高 / 显存告警处理说明（课题组服务器）

> **适用场景**：组内训练服务器、共享 GPU 节点；常与 CPU 高负载、I/O 或作业调度问题并存。CPU 通用排查见 `cpu_high_usage.md`。

## 与「206 服务器监控」快照的关系

- 当前 Prometheus 快照（`getLabServerRuntimeSnapshot`）**不包含 DCGM / GPU 利用率**字段，仅有机体 CPU、内存、根盘、负载与网络。问「GPU 现在怎样」须结合登录后 `nvidia-smi` 或专用 GPU 监控；整机资源可先引用快照中的 `cpuPercent`、`memoryPercent`。  
- 总览见 `lab_server_snapshot_and_actions.md`。

## 典型现象

- `nvidia-smi` 中 GPU-Util 长期接近 100%，或显存占用（Memory-Usage）接近上限  
- 多用户排队、新任务 OOM（显存不足）  
- 单个僵尸进程占用 GPU 不释放  

## 排查思路（按权限执行）

1. **确认时间与节点**：记录告警时间与主机名，便于对照作业日志。  
2. **查看 GPU 状态**：`nvidia-smi`，关注进程 PID、显存、利用率。  
3. **定位进程与用户**：结合系统 `top`/`htop`、集群调度器（Slurm/PBS 等）的作业列表，确认是否为预期训练任务。  
4. **显存泄漏或异常占用**：联系任务所有者协调释放；必要时由管理员 `kill` 明确无人认领的进程（遵守组内规章）。  
5. **公平与配额**：若组内采用分区或时间片，在文档中写明**申请方式**与**优先级规则**（在此补充你们组的实际政策）。

## 与 Prometheus / 日志

若已对接监控：在 Prometheus 或云监控中查看 GPU 温度、功耗、XID 错误等指标；日志中检索驱动报错、CUDA OOM 关键字。

## 应急小结

- 先区分「正常满载训练」与「异常占用」  
- 优先协调用户释放，再考虑管理员介入
